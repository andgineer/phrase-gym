# Bounded English lesson delivery

The production Rust API currently accepts one English lesson of one to five short fixed phrases per submission, each with supplied reference audio. The browser supports bounded supplied-audio input; automatic browser intake and Coach CLI preparation remain preview work. This API path needs no Coach process or provider credentials to accept and retain input or serve published material.

Start Server with the [documented Rust command and scoped credentials](../README.md). Use separate Bearer credentials with `material_submit` and `worker` capabilities; profile updates require separate authority. Generated request/response schemas live in [Rust OpenAPI](../frontend/tests/rust-contract/openapi.json).

1. Upload each original through `POST /api/v1/media`, including exact English text, reference role and performer/source provenance. Retain the returned media ID and SHA-256. Uploads verify the complete container, hash and durable core file before returning. Retries retain the same media identity.
2. Send `POST /api/v1/inbox/lessons` with a stable `submission_id`, sender-local `item_id`, `expected_generation: null`, English language, title, context, note and one to five `phrases`. Each phrase carries stable `source_id`, exact `text`, `reference_audio_id`, `audio_sha256` and `expected_revision: null` for a new target. Persist exactly these bytes/identity until the durable lesson receipt returns. The authenticated actor supplies sender identity.
3. Read `GET /api/v1/inbox/lessons/{generation_id}` with learner or material-submit authority for the same sender actor. Identical submission retries recover the original receipt. Changed payloads under that identity conflict. A changed note or explicit reprocessing uses a new submission ID and the previous `expected_generation`; existing targets also require their current expected revisions. This creates a new immutable generation and fences unfinished older work.
4. A worker uses `POST /api/v1/preparation/claims` with a stable `claim_id`. The claim returns pinned input, profile, guide, namespace, generation and fence. No work returns JSON null; retrying that claim ID returns its original result. Use a fresh claim ID for the next poll. Download only this claim's original audio through `POST /api/v1/preparation/audio` with its fence and media ID.
5. Prepare outside Server transactions. Renew through `/api/v1/preparation/renew` with the fence. Upload any supplied situation/partner clips through the media endpoint. Submit `/api/v1/preparation/stage` with the fence, stable `publication_id`, adapter identity and `PreparedEnglishLesson`. Preserve the pinned namespace/profile/guide, source revision equal to the generation number, input phrase identities, exact wording, original reference IDs and expected revisions. Unsupported or invalid output fails actionably; unknown meaning can be reported through `/api/v1/preparation/fail` with a reason.
6. Submit the fence to `/api/v1/preparation/publish`. Publication rechecks lease/generation and target revisions and atomically commits all lesson content and its receipt. After a lost response or restart, query `/api/v1/preparation/receipt` or retry publish with the same fence. Staged publication identities retain their exact adapter/package payload across claim replacement; changed output needs a new publication ID. A committed receipt remains recoverable after lease expiry; expiry never permits a new write. Do not invent new identities to resolve an ambiguous acknowledgement.

## Browser first lesson

After selecting English, choose **Add a first lesson** in the Library. Enter one exact fixed phrase, a lesson title, its situation or meaning, optional note, performer and audio locale. Select its original WAV, MP3, OGG or MP4 reference clip (up to 2 MB), then choose **Submit lesson**. Opening or closing the input panel sends nothing. Other learning languages show the current English-only intake limit without changing their existing library.

The browser saves the immutable input and audio locally before transfer. A delivery error retains that input; **Retry the same delivery** reuses its identity and bytes, including after reload. Discarding a local unconfirmed delivery is explicit and does not cancel work that may already have been accepted. After acknowledgement, Server owns the input even with Coach offline. Open the panel and choose **Check lesson status** to distinguish waiting for Coach, preparation, failure, pending publication and confirmed publication. Failed preparation shows its reason and offers a retry subject to Server's attempt budget. Only one local delivery is retained at a time; after publication, **Add another lesson** clears that local copy.

The current access system may deny browser submission: learner-only connections can read their own inbox status but cannot upload material or submit it. The error retains the local input and asks for operator assistance. No credential-entry field is provided here. Automatic access setup and automatic paste/drop preparation remain next-stage release blockers; this manual preview form does not satisfy them.

**Open published lesson** links to the actual lesson. Reference-only English content supports opening a phrase to listen, record, compare and replay saved takes. It is shown as ready for reference rehearsal, separately from scheduled retrieval counts; scheduled Start stays unavailable when there are no eligible targets. A published lesson and zero scheduler counts can coexist. This preview does not implement first-study sessions or English scheduled retrieval.

## Worker operation

Sender cancellation and explicit retry of a failed generation use `/api/v1/inbox/lessons/{generation_id}/cancel` and `/retry`. Retry preserves the attempt budget. A job has at most three starts, a 120-second renewable lease and a ten-minute absolute attempt deadline. Server enforces a durable global budget of twenty preparation starts per UTC day. Encoded audio is limited to 17,000,000 base64 characters by the upload service; staged output is limited to 100,000 JSON bytes. Context is limited to 8,000 bytes and the learner note to 2,000 bytes. These preview limits are enforced by Server and do not reset when Coach restarts.

The fake-worker acceptance tests exercise production routes without SQL intake or seed routes: `cargo test -p phrase-gym-server --features test-support --test api inbox`. Domain tests cover concurrent claims, stale workers, expected revision conflicts, rollback, budget retention and isolated restore: `cargo test -p phrase-gym-core --test inbox`. These checks establish software behavior; they do not establish model semantics, speech quality, browser practice acceptance or a complete Coach workflow.
