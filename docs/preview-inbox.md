# Bounded English lesson delivery

This page documents the current Rust prototype API, not a contract the Python replacement must preserve. The new [material input](../specs/decision-external-preparation-agent.md) starts with a user-imported batch and has no external worker API.

The prototype Rust API currently accepts one English lesson of one to five short English items per submission, each with verified supplied or generated reference audio. The browser previews text with an optional note and submits only on Send. The [Coach text-only demo](coach-desktop.md#local-english-lesson-demo) accepts text durably through this same contract, then prepares targets and generates exact reference speech before publication. This API path needs no Coach process or provider credentials to accept and retain input or serve published material.

Start Server with the [documented local connection](rust-preview.md). The operator on the same MacBook needs no application credentials; profile updates remain an explicit operator workflow. Generated request/response schemas live in [OpenAPI document](../frontend/openapi.json).

1. Upload each reference through `POST /api/v1/media`, including exact English text, reference role and supplied performer/source or generated engine/voice/speech-input provenance. Retain the returned media ID and SHA-256. Uploads verify the complete container, hash and durable core file before returning. Retries retain the same media identity.
2. Send `POST /api/v1/inbox/lessons` with a stable `submission_id`, sender-local `item_id`, `expected_generation: null`, English language, title, context, note and one to five `phrases`. Each phrase carries stable `source_id`, exact `text`, `reference_audio_id`, `audio_sha256` and `expected_revision: null` for a new target. Persist exactly these bytes/identity until the durable lesson receipt returns. The current local mode attributes input to one shared private operator.
3. Read `GET /api/v1/inbox/lessons/{generation_id}` through the same private connection. Reconcile `GET /api/v1/inbox/submissions/{submission_id}` before retrying an ambiguous delivery; it returns the operator receipt or null. Identical submission retries recover the original receipt. Changed payloads under that identity conflict. A changed note or explicit reprocessing uses a new submission ID and the previous `expected_generation`; existing targets also require their current expected revisions. This creates a new immutable generation and fences unfinished older work.
4. A worker uses `POST /api/v1/preparation/claims` with a stable `claim_id`. The claim returns pinned input, profile, guide, namespace, generation and fence. No work returns JSON null; retrying that claim ID returns its original result. Use a fresh claim ID for the next poll. Download only this claim's original audio through `POST /api/v1/preparation/audio` with its fence and media ID.
5. Prepare outside Server transactions. Renew through `/api/v1/preparation/renew` with the fence. Upload any supplied situation/partner clips through the media endpoint. Submit `/api/v1/preparation/stage` with the fence, stable `publication_id`, adapter identity and `PreparedEnglishLesson`. Preserve the pinned namespace/profile/guide, source revision equal to the generation number, input item identities and original source_text, fixed-phrase wording, original supplied reference IDs and expected revisions. Frames declare patterns/slots and complete examples; words declare two or three gapped contexts with matching whole-sentence answers and exact reference IDs. Unsupported or invalid output fails actionably; unknown meaning can be reported through `/api/v1/preparation/fail` with a reason.
6. Submit the fence to `/api/v1/preparation/publish`. Publication rechecks lease/generation and target revisions and atomically commits all lesson content and its receipt. After a lost response or restart, query `/api/v1/preparation/receipt` or retry publish with the same fence. Staged publication identities retain their exact adapter/package payload across claim replacement; changed output needs a new publication ID. A committed receipt remains recoverable after lease expiry; expiry never permits a new write. Do not invent new identities to resolve an ambiguous acknowledgement.

## Browser first lesson

After selecting English, use the global **+** or Library first-lesson action. Review one to five items, one per line, optionally add a note, then **Send**. The clipboard is read only on the + gesture; denied/empty access leaves an editable preview. Opening or closing it sends nothing. Ordinary words and complete phrases are enough: Coach infers word senses and reusable constructions wherever defensible from the text, available context and pinned preferences. Prepared material, explicit context and audio belong to the external-agent API path. Required preferences are never silently changed.

The browser retains exact submitted context, item identities and original wording until Server acknowledgement. A lost response reconciles the same submission ID before retransmission. Server owns accepted work with Coach offline. Status polling distinguishes accepted/waiting, preparing, failed and confirmed publication. Failed preparation offers an explicit retry under the existing attempt budget. One local delivery is retained at a time; **Add another lesson** clears the completed local copy.

A failed private connection retains local input and explains recovery. Browser intake needs no token or login. The replacement's [local access boundary](../specs/architecture.md#local-access-and-privacy) requires no social sign-in. The bounded native Codex/Piper text path is documented in [Coach setup](coach-desktop.md); broader prototype intake is not a prerequisite for the reduced MVP.

**Open published lesson** links to the actual lesson. The normal **Start session** and **Start lesson drill** actions open bounded English material as ungraded study with its phrase, situation, pinned help and reference audio. Recording is optional; a completed capture compares the saved take with the reference. **Next** completes the presentation without a memory rating, scheduler update or claim that speech occurred. Once Next durably completes study of that revision, a later Start shows its situation with the phrase hidden until reveal. Self-ratings become available after reveal/comparison and refer to the original silent or recorded response. Eligible independent recall initializes or updates the schedule; supported, technical and stale responses retain their exclusions. A provisional unassessed check does not block this first recall, while assessed future obligations stay excluded. Published content, reference and saved takes survive browser reload and Server restart with Coach closed. Opening intake from a study card releases active media, preserves recoverable takes and keeps the initiating attempt ungraded.

## Worker operation

Sender cancellation and explicit retry of a failed generation use `/api/v1/inbox/lessons/{generation_id}/cancel` and `/retry`. Retry preserves the attempt budget. A job has at most three starts, a 120-second renewable lease and a ten-minute absolute attempt deadline. Server enforces a durable global budget of twenty preparation starts per UTC day. Encoded audio is limited to 17,000,000 base64 characters by the upload service; staged output is limited to 100,000 JSON bytes. Context is limited to 8,000 bytes and the learner note to 2,000 bytes. These preview limits are enforced by Server and do not reset when Coach restarts.

The fake-worker acceptance tests exercise production routes without SQL intake or seed routes: `cargo test -p phrase-gym-server --features test-support --test api inbox`. Domain tests cover concurrent claims, stale workers, expected revision conflicts, rollback, budget retention and isolated restore: `cargo test -p phrase-gym-core --test inbox`. These checks establish software behavior; they do not establish model semantics, speech quality, browser practice acceptance or a complete Coach workflow.
