# Phrase Gym Coach desktop

Coach prepares content through Server's durable inbox. Practice stays in the built Vue client served by Rust Server. The local demonstration supports one new fixed English phrase at a time; the full multilingual content and learning-loop MVP remains in the [implementation plan](../specs/plan/implementation-plan.md).

## Build, run and smoke-test

Use Node from `.nvmrc`, then:

```bash
cargo xtask app-build
cargo xtask coach-bundle
```

The unsigned macOS bundle is `target/coach-bundle/Phrase Gym Coach.app`. `cargo xtask coach-smoke` launches the packaged smoke checks; these native checks require attended authorization. Never trigger native dialogs or login automatically. Windows builds retain their platform tests; actual Windows CLI qualification remains pending.

## Local English lesson demo

Run the matching Server with the built client and the existing standard Server data directory. If a Server already owns the port, stop it gracefully before starting the matching build; preserve its database and media. Do not create an isolated demo data copy or import a prepared lesson:

```bash
target/release/phrase-gym-server serve --data-dir "$HOME/Library/Application Support/io.github.andgineer.Phrase-Gym-Coach/demo-server" --client-dir frontend/dist --port 18487
```

Follow the [standing local English demo authorization](../specs/plan/implementation-plan.md#standing-authorization-for-the-local-english-demo). Reuse the existing Codex subscription login and installed local Piper configuration; no new budget, workspace or authentication setup is needed for routine demo runs. Piper needs no authentication. The setup sections below apply only when an actual missing prerequisite is reported. Run from this repository:

```bash
cargo run -p phrase-gym-coach --bin phrase-gym-add-text -- "Let's get started." http://127.0.0.1:18487
```

The command saves this repository as Coach's workspace, checks the pinned Codex version and ChatGPT subscription status, saves the raw original text in Server before generating reference speech, then uploads verified WAV bytes under its fenced claim, prepares with Codex and atomically publishes through Server. An existing Coach instance must be quit first. Opening the bundled Coach afterward uses the saved workspace. Deliberately pasting one exact English phrase into **Material draft**, or dropping a local UTF-8 `.txt` file containing that phrase (up to 200 bytes), starts the same speech/intake workflow. Dropped directories, symlinks, oversized files and non-text attachments fail inline. Typing alone and opening the window do not submit. External agents may supply prepared packages and original audio through the API; invalid supplied audio is rejected instead of replaced.

Open the printed local browser URL, choose **Start session**, and use the published material. Reference playback remains available with Coach closed. After ungraded study, choose Next, return to Library and start a later session: the same revision now shows only its situation prompt until reveal. Rate the original silent or recorded response after reveal/comparison; study itself creates no memory state or success. This bounded fixed-phrase demonstration remains an internal checkpoint; all content forms, multilingual preparation and actual-device acceptance remain MVP work. No prepared lesson is seeded by ordinary text intake. Neither ordinary web nor Coach intake offers manual lesson fields or prepared-file controls.

In the browser, the global **+** opens a clipboard preview over the current screen. Denied, empty or unavailable clipboard access leaves an editable box. Review the phrase, optionally add a note, and press **Send**; nothing from the preview is transmitted before Send. The original card and any retained capture stay bound to their initiating attempt. Clipboard reads occur only in the + gesture and late results cannot replace edits or reopen a closed preview.

**Practice now** appears when Due and New are zero and material is ready, and after a completed round. It starts a voluntary round in the current language and lesson scope, with up to 20 ready targets. An unfinished round resumes instead of being replaced. Ratings and every take are retained, but voluntary ratings never change due times or memory state or count as independent recall, including with help or failure. Genuine first study still uses ungraded Next and keeps later first-check eligibility. If nothing is ready, the client explains that valid cues and reference audio are needed.

One input can be outstanding locally. Browser storage and Coach's `pending-text.json` retain exact raw text and stable submission identity until Server acknowledges durable receipt. A crash or lost receipt retries that same identity; it does not synthesize before acceptance. Server owns accepted generations, leases and publication receipts. A generation-bound local reference checkpoint retains generated bytes and the normalized model input, so an explicit model retry reuses speech rather than synthesizing it again. A failed attempt requires explicit preparation retry through its browser status panel or Coach's retry action. `phrase-gym-add-text --retry-preparation "the same phrase" http://127.0.0.1:18487` verifies the retained accepted text and origin before requesting retry. A local Server outage is distinct from publication.

### Bounded Piper speech proof

The English demo candidate is `en_US-ljspeech-medium`, Piper 1.8.0, ONNX Runtime 1.x, one speaker, 22,050 Hz. The [model card](https://huggingface.co/rhasspy/piper-voices/blob/c10ece1aade47bb51c153c893d14e5bf8e5b7117/en/en_US/ljspeech/medium/MODEL_CARD) identifies scratch training on [LJ Speech](https://keithito.com/LJ-Speech-Dataset/), whose author declares the dataset public domain without use restrictions. The voices repository declares MIT in its [README metadata](https://huggingface.co/rhasspy/piper-voices/blob/c10ece1aade47bb51c153c893d14e5bf8e5b7117/README.md). This choice avoids assuming acceptance of Lessac's research-data terms. Primary voice quality still requires attended listening.

Download the model and adjacent JSON configuration from that exact Hugging Face revision into an external cache. Configure `piper-voice.json` in Coach's settings directory, using absolute paths:

```json
{
  "executable": "/absolute/path/to/python-with-piper-1.8.0",
  "runtime_version": "1.8.0",
  "model": "/absolute/path/to/en_US-ljspeech-medium.onnx",
  "model_sha256": "6f52a751e2349abe7a76735eb09dc1875298c77ea2342ffd2fef79ff81b87f22",
  "config": "/absolute/path/to/en_US-ljspeech-medium.onnx.json",
  "config_sha256": "141d612cc0a95ed7efc1ca936b845c2364967f2e9217c5dbfcf69fc4d6c65860",
  "voice": "en_US-ljspeech-medium",
  "locale": "en-US"
}
```

The interpreter uses isolated mode. The speech runner verifies package versions, hashes, locale and speaker count, stages immutable bytes outside repositories, supervises a maximum 60-second process with bounded output, then validates nonempty PCM and returns WAV. Exact text, speech input, voice, runtime identity, model/config hashes and settings accompany generated media. A failed synthesis retains text and publishes nothing. These checks establish byte/provenance conformance, not pronunciation or listening quality. German and Serbian voices remain unaccepted.

Use native Codex 0.163.0 (Homebrew cask on macOS). Coach resolves its canonical executable without shell initialization. Node-script CLI installs are unsupported. Reuse the existing login and verify `codex login status` says `Logged in using ChatGPT`. Only when that login is actually absent does first-time setup require the learner to run `codex login`. API-key logins fail readiness, and exported API keys/proxies/parent agent sessions are excluded from the child environment.

At the learner's explicit direction, local Coach uses the normal Codex home and this repository as its working directory. Normal-home and repository instructions and skills may load; this configuration does not claim isolation from them. `--ignore-user-config` excludes config.toml settings, and `--ignore-rules` excludes execpolicy .rules loading, while the explicit preparation prompt remains authoritative for its task. ## Verified CLI invocation

### Every attempt

The prompt, pinned input/profile/guide and schema live in a private attempt directory; the short bootstrap names the absolute prompt path. Standard input stays closed. Process supervision owns output bounds, cancellation, stream closure, deadlines and descendant cleanup. Exit zero with malformed, empty, truncated or changed-identity output is a failure. Publication requires a current fenced Server lease and verified exact reference bytes.

### Readiness, failures and usage

Codex checks exact native version and ChatGPT status before execution. Authentication/quota errors stop preparation until explicit retry. Unparsed token usage stays unknown to the runner; bounded measurements inspect the anchored `tokens used` stderr trailer when available. Timing and schema validation do not imply semantic acceptance. Private provider output is separate from sanitized status. Server receipts, rather than a CLI success message, confirm publication.

### Codex

The argument builder pins `exec --skip-git-repo-check --ignore-user-config --ignore-rules --ephemeral`, model `gpt-5.6-luna`, low effort, `forced_login_method="chatgpt"`, approval `never`, web search disabled and no persisted history. Apps, browser/computer/image tools, goals, hooks, plugins, multi-agent execution and image reading are disabled. The environment is allowlisted and `CODEX_HOME` points directly at the normal home.

The staged generated-contract schema is passed through `--output-schema`, with closed objects, required nullable fields and a source-word-only hint enum; malformed output is never repaired by the runner.

An explicit permission profile denies filesystem root, permits minimal system/runtime reads and Codex installation reads, denies shared temporary paths, permits the repository workspace with an explicit `.env` denial and disables command network access. Repository cwd intentionally permits repository access; it is no longer an attempt-only workspace. This is a local trusted-user configuration, not a claim that normal-home customizations are isolated. A native OS sandbox check with a synthetic temporary `.env` confirmed that ordinary workspace input is readable while that secret-file rule denies reads; no real `.env` was opened and no model was started for this check. Recheck affected behavior on version/configuration changes.

## Bounded synthetic measurement

On 2026-10-20, the frozen English development input “Let's get started.” traveled through the actual text-intake workflow with native Codex 0.163.0 (`gpt-5.6-luna`, low effort), the normal user Codex home and repository cwd, Piper 1.8.0/ONNX Runtime 1.31.0 and the pinned LJSpeech model above. Authorization bounded the run to at most three Codex starts (90 seconds/64 KiB per stream) and three local speech starts (60 seconds/2 MB output); two Codex starts and one synthesis were used. No paid API or automatic provider retry was used.

The first model output was rejected as malformed JSON (16.385 seconds; CLI reported 18,360 total tokens). Fresh semantic review also identified a stem hint and weak action wording. After enforcing the staged schema, whole-source-word hint choices and explicit situation intent, an explicitly requested retry reused the same generated WAV. The second result validated and published atomically (13.383 seconds; CLI reported 19,184 total tokens), with hint “started”, two natural action prompts, English help, no translation and new familiarity. A fresh reviewer accepted that result separately from structural checks. The 54,828-byte generated reference retained its exact identity through the retry. Normal built-client Start displayed the published phrase, prompt, help and reference action. Listening and actual microphone/output acceptance were not performed; this single English measurement establishes neither multilingual quality nor the full MVP.
