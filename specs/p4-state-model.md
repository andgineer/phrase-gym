# Superseded offline P4 state model

**Historical offline-era model, superseded by [online-only behavior](decision-online-only.md). Connected retention/cleanup protections survive, but offline projection/packs/lifecycle/readiness do not.**


Accepted 2026-10-13 under the confirmed pre-round-4 audit. This specifies the facts, owners and admission rules shared by ordinary practice, lookup and prepared dialogue flows. It extends the [offline decision](decision-offline-sessions.md); the [coverage matrix](plan/evidence/p4-state-matrix-2026-10-13.md) maps these rules to actual implementations and combined behavioral checks.

## Independent state owners

| State | Owner and durable representation | Authority and transition |
|---|---|---|
| Capture resource | One component-scoped `useCapture` instance; a per-take Web Lock and `take-v2:` marker | Permission request → leased recording → stop/interruption → pending final bytes. Cancel/navigation/background releases tracks; late permissions cannot restart the recorder. Only the lease owner writes nonempty capture bytes. |
| Pending recording bytes | Application-lifetime `takeTransfers`; IndexedDB take entry plus volatile map if storage fails | Capture ownership and byte ownership are separate. A component can disappear while the application still owns final volatile bytes and the lease. Retry makes the exact bytes durable before releasing the capture lease. Tab loss cannot preserve volatile-only bytes. |
| Server recording | `RecordingService`, SQLite BLOB and immutable canonical metadata/hash | Exact same-ID retry returns the same receipt. Different bytes/context under that ID conflict. Every new take has a new ID. Events/exposure receipts establish context before audio can be accepted. |
| Event intent | `usePracticeEvents`, original-ID sequenced IndexedDB outbox | Write before projection. Retry original payload/ID. Receipt checkpoint commits before local outbox deletion. A conflict is retained separately before removing the active entry. |
| Acknowledged checkpoint | Server session/events/attempts; monotonic `journalCheckpoint` mirror | Sequence/version order session state; independently appended exposure facts merge by target/time union even at equal or rejected-older counters. A delayed read cannot erase retained facts. Different sessions are selected by recency, not event count. |
| Displayed session | `usePracticeSession` with loading generation, pending projection and lifecycle overlay | Restoring → projected display → available controls. Rendered provisional completion is distinct from acknowledged completion. New user actions are blocked until restoration finishes; navigation/cancel/stop remain available. |
| Device lifecycle intent | `deviceSessionState`, explicit `lifecycle:{id}` active/paused value | First origin-loss transition journals local intent if a compatible verified pack exists. Overlay on every load/receipt, including zero-outbox reload. Completed/superseded authoritative states override local intent. A connected explicit transition uses the acknowledged version and clears the overlay only after acknowledgement. |
| Exposure facts | `practice/support.py`, lookup receipts and practice event receipts; generated `support_exposures` session contract | Facts bind a target and actual exposure occurrence time. The checkpoint carries applicable facts since session start minus five minutes; queued local exposures add their original times. A rating/finalization is never an exposure. |
| First response | Server and pure client attempt state, immutable `original` snapshot | First respond/answer/rate snapshots modality/support before the current answer reveal. Later help, repeated takes, ratings and retries cannot relabel it. Technical capture states affect eligibility separately. |
| Offline pack/update | `sessionPack`, shared per-pack readiness publication, selected-media cache, versioned worker shell and `pwa` | Every restored/action readiness check verifies the complete shell and byte/hash media, not only explicit download. Failed verification clears shared readiness; older verification results cannot republish it after a newer check. Pack version 3 requires explicit exposure chronology. Earlier packs require a connected redownload, retaining queued evidence. Updates wait at pause/end and refuse pending events, durable/volatile takes, capture or restoration. Old shell assets remain usable by existing tabs. |

## Invariants and admission rules

**R1 — byte ownership survives view changes.** An incomplete/complete final take belongs to the application transfer owner after capture stops. Library, Settings, learning-language navigation, completion and foregrounding cannot dispose of it. A live or frozen lease cannot be reclaimed by a timeout. Recovery claims an available lease, rereads the current entry, then conditionally converts nonempty abandoned bytes to incomplete pending or removes an empty marker. Legacy unleased captures are retained for compatible recovery; their finished pending takes remain transferable. New namespaces isolate incompatible writers.

**R2 — acknowledgement never deletes a different value.** Hold the available take lease through upload/receipt processing. Validate ID, size, SHA-256 and completeness against the uploaded value, then compare all current metadata and every current byte in one IndexedDB write transaction. Same-size replacement is still a replacement. A changed value remains locally retained with a visible error; a server ID conflict does not authorize overwrite, relabeling or deletion. Independent valid takes continue transferring.

**R3 — intent and authority are distinct.** Active/paused device intent survives origin loss and empty-outbox reopening. Closed authoritative sessions win. Immutable manifest language/content/cue/group bindings do not change during navigation, takeover or old-outbox ingestion. One eligible group updates a schedule once; historical/conflicting outcomes remain evidence rather than new grades.

Checkpoint order is a product of session counters and independently appended facts. A target lookup can add support facts without changing session sequence, version or updated time. Retain the newest session state and union acknowledged exposure facts in the same IndexedDB transaction, including equal-counter and rejected-older reads. Do not union/recompute original responses; only the independent target/time fact set is monotonic.

**R4 — support uses exposure facts.** Before a first response, `supported = previously observed support on this attempt OR any matching-target exposure in [event time − five minutes, event time]`. Both endpoints are inclusive; future facts do not count. Lookup uses its server receipt time; on-card answer/explain/reference/capture-complete and dialogue script use their authoritative event occurrence times. Dialogue script exposes each bound target. Help can remain observed on an existing attempt after the window expires, while a later distinct/repeated attempt starts from actual still-recent facts. The original response is never recomputed. Rating timestamps, dialogue membership, reveal booleans and recording upload time cannot stand in for exposure time. Local times are provisional; server clock normalization and receipts remain authoritative.

**R5 — restoration precedes new interaction.** Load the latest retained checkpoint, project all pending actions by sequence, overlay local intent, then allow preparation and new user actions. No transient raw introduction creates a new script exposure. `usePracticeActions` owns preparation/audio effects; views render state. The event adapter rechecks admission at the serialized command boundary. Existing capture-complete/failure observations remain admissible during restoration so resource cleanup can retain technical evidence; they still obey card/session binding. Loading generation prevents obsolete routes from becoming current.

Control of an owned resource precedes new-action admission: the shared button stops active capture/playback or cancels a pending permission even while restoration or another busy state blocks starting new media. A single busy prop cannot disable both start and cleanup. Cancellation releases late streams, and ordinary manual stop retains a complete take without waiting for a held session read.

Resource affinity is the initiating practice session/step or lookup target/revision. Capture context and reference URL are pinned before awaiting effects. An authoritative card replacement or lookup target change releases its old resource; recoverable old bytes remain attributed to the old context. Late completion/replay/comparison cannot attach to the new card or look up its reference dynamically. These rules apply to lookup controls as well as practice.

**R6 — compatibility and update never consume retained evidence.** A pack readiness claim requires its explicit version, immutable manifest, complete shell and all selected assets. Quota/missing/evicted state blocks that promise. Storage failure never claims saved audio or an advanced rating. A waiting update cannot reload over pending bytes/events, capture or restoration. It may proceed after exact acknowledgements at a safe checkpoint. Browser storage is a journal/cache, not P6 backup.

## Boundaries

No arbitrary offline library access or new session planning is promised. A lost browser store cannot reconstruct unacknowledged bytes from the server. Actual iPhone Safari/installed-PWA, secure phone origin, speaker/headset, real speech/interruption, persistence and VoiceOver acceptance remain in the [runbook](plan/p4-runbook.md), separately from desktop engineering evidence. P5 content/provider integration and P6 deployment/backups are unchanged.
