# Acceptance gaps

Automated checks establish software behavior, not device output, linguistic quality or successful recovery on a deployed host.

- **Blocking recording defect:** the learner reports playback becoming silent midway through every take in the current demo. Restore complete capture/replay/comparison and verify separately identified saved takes after reload and Server restart with learner-triggered physical microphone/output checks before accepting the demo. The earlier successful Safari capture/comparison retest does not establish current behavior. Synthetic capture cannot certify physical microphone input or device output. Headsets, iPhone clipboard/Paste, background/phone interruptions, pause/resume, VoiceOver and enlarged/non-Latin text retain their separate acceptance gaps.
- **Content and reference speech:** actor/course clips and prepared Serbian content/speech need semantic/listening acceptance. Development fixtures and positive container checks are not an accepted release language pack. The local 44-phrase pack still uses one manual gapped cue per phrase; it does not establish Phrase Gym Coach's preparation quality.
- **Phrase Gym Coach:** automated checks cover the status window, packaged launch and fake-process cleanup. The separate native Settings window has an upstream eframe 0.37 AccessKit gap: only root viewports initialize the adapter, so Settings controls are absent from the native accessibility tree. Manual provider-backed probes, not automated checks, confirmed both CLI permission boundaries on macOS; the Codex probes ran in the operator's own Codex home with user configuration ignored. The local MVP still needs attended VoiceOver/Finder acceptance on the actual MacBook. Narrator, Start-menu launch, Windows Remote Desktop rendering and wider OS qualification are deferred release gaps. Codex uses the normal user home and repository workspace by explicit local preference; normal-home customization isolation is not claimed; both CLIs on Windows are deferred qualification. Sleep/recovery, the bounded preparation worker, shared-core inbox/preferences APIs, cross-entry matching and unattended material quality also need acceptance. Required Serbian help/proficiency preferences remain unresolved. Source browsing/login and URL import are outside the inbox.
- **Private release:** core hosting/access policy, scoped worker/API access, resource fit, practice/submission/preferences with Coach offline, job recovery, consistent single-database/media backup/restore and upgrade/rollback remain unverified.

Concrete remaining tasks are in [the implementation plan](plan/implementation-plan.md). Keep learner data and recordings private; use disposable data for automation.
