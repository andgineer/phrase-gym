## Finding

### 1. [P2] Apply the script-exposure window to provisional dialogue support

**Trigger:** download a prepared dialogue with at least two distinct target turns, begin rehearsal, and spend more than five minutes on the first turn while disconnected. Rate it, then respond to a later target without additional help.

**Expected:** when no qualifying exposure remains within the accepted five-minute window, the later target's provisional original response and results should reflect independent recall, consistently with server reconciliation. Mere membership in a dialogue does not constitute a fresh script exposure.

**Actual:** every newly projected dialogue attempt is unconditionally supported. The card says **With help**, and local completed results retain that label. Reconnection changes the same original response to `supported=false` and removes the label because the server correctly recognizes that the script exposure expired.

**Evidence:** `frontend/src/offlineProjection.ts:42-49` starts the support expression with `Boolean(next.manifest.dialogue)`, ignoring the script event's occurrence time. Lines 27-28 return from dialogue events without retaining their exposure chronology, and lines 60-65 snapshot this unconditional flag into the provisional original response. The server instead checks the actual dialogue-exposure event receipt against the five-minute interval in `src/phrase_gym/practice/evidence.py:52-67`, then uses that result when creating the attempt at lines 73-90. The card renders this support at `frontend/src/components/PracticeCard.vue:126-132`, and completed results render `attempt.original.supported` in `frontend/src/components/PracticePanel.vue:188`.

**Deterministic reproduction, confirmed in Chromium and WebKit:** use the built production client and a disposable real server with a synthetic two-target dialogue. Begin and download while connected. Advance both server and browser event clocks by six minutes, sever a disposable TCP proxy, rate the first target, then present/rate the second without reveal, explanation, reference playback or recording. Both browsers show **With help** on the second card and `I’d rather meet tomorrow. — Recalled · With help` in locally finished results. Reconnect and dispatch the online signal: the same server attempt has `original.supported=false`, `eligibility_reason=eligible`, and its confirmed result reads `I’d rather meet tomorrow. — Recalled`. Controlled clock advancement avoids a six-minute wall-clock wait while preserving the production event/receipt and exposure-window logic. A separate controlled-clock real-API fixture and direct execution of the production projection reproduced the same true-versus-false original-support mismatch.

**Impact and scope:** provisional support evidence and learner-facing results are inaccurate during ordinary longer offline dialogue rehearsal. Authoritative server grading remains correct in this reproduction; no duplicate schedule advancement, audio loss or immutable server-response rewrite was established. This is a fixable engineering inconsistency, independent of phone acceptance.

**Correction:** retain the relevant script-exposure chronology for local projection, including reopening after its events have been acknowledged, and apply the accepted time window rather than blanket dialogue support. Add a deterministic real-browser regression with distinct target turns, expired versus recent script exposure, offline reopening and reconciliation. Preserve original-response snapshots, existing on-card support, immutable dialogue bindings and authoritative receipts.
