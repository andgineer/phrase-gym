## Findings

### 1. [P1] Keep quota-failed audio outside component lifetime

**Evidence:** `frontend/src/composables/useTakeJournal.ts:17-30` retains failed writes in a Map constructed per composable instance, while its new recovery instruction promises that audio remains in the open tab. `frontend/src/App.vue:124-130` unmounts PracticePanel when Library, Settings or a different language is shown. A new panel constructs a new take journal, and `frontend/src/composables/useCardAudio.ts:88-90` revokes the previous local replay URL. Neither the bytes nor their storage error are owned by an app/tab-level recovery service.

**Reproduction, confirmed independently in Chromium and WebKit:** download a session; use a synthetic MediaStream and real MediaRecorder; make only non-empty `take:` IndexedDB puts throw `QuotaExceededError` (allow the initial zero-byte capture marker); record until the keep-open warning appears and stop. The local take can play, SQLite has no recording, and the UI says to keep the tab open and retry. Click Library, restore successful IndexedDB writes, then click Resume session using SPA navigation. Do not close or reload the tab. The warning disappears, My recording becomes disabled, the journal contains only a zero-byte marker, and the server recordings list remains empty. Retry in the new panel cannot recover the original bytes. With full reload the empty marker is removed as well.

**Impact:** a recoverable take becomes inaccessible and cannot reach SQLite despite following the keep-open instruction. This violates every-take retention and the P4 quota recovery contract. The component-local Map predates P4, but it remains a concrete defect in the complete reviewed result and P4's newly claimed quota recovery; this is not a request to restart a generic P3 review.

**Correction:** own volatile takes and their recovery/error state at tab/application lifetime, preserving per-take context through panel unmounts; wire global retry, pending counts and update guards to that owner. Alternatively, explicitly prevent component-destroying navigation until volatile evidence is safely retained, with accurate guidance. Do not treat an empty journal marker as retained audio. Add a real-browser quota → stop → Library/Settings/language navigation → return → retry test that acknowledges the same original ID/hash/bytes exactly once.

### 2. [P2] Restore both local lifecycle states on every load

**Evidence:** `frontend/src/composables/usePracticeSession.ts:99-102` persists offline pause as presence of `paused:<id>`, but persists offline resume only by deleting that key. `frontend/src/composables/usePracticeEvents.ts:43-45` can overlay paused onto active; it cannot overlay active onto a server-paused checkpoint. The successful load path at `frontend/src/composables/usePracticeSession.ts:136-140` directly accepts the checkpoint and only invokes projection indirectly when flush has an event receipt. With an empty outbox it does not apply the local pause marker at all.

**Reproduction, confirmed independently in both engines:**

1. Download, disconnect, rate a card, pause, reconnect and dispatch the online signal. The queued events reconcile and the panel is initially still paused. Reload online after the outbox drains: the panel becomes active despite the retained local pause key and no explicit Resume action.
2. Pause online so the acknowledged checkpoint is paused. Disconnect and reload, then Resume session offline. The panel becomes active. Reload while still offline: it becomes paused again because deleting the marker does not override the paused server checkpoint.

**Impact:** pause does not reliably prevent practice on this device, and offline resume does not survive reopening, contrary to the accepted device-local lifecycle contract. These are implementation defects independent of phone/HTTPS acceptance.

**Correction:** persist explicit local desired lifecycle state, including active, independently of acknowledged server state. Apply its compatible overlay in both successful and offline load paths, including zero-event reconciliation. Closed/superseded authoritative sessions must still win, and connected lifecycle changes must retain version validation. Add both reproductions as browser regressions; the current offline test starts from a server-active checkpoint and does not cover either boundary.

### 3. [P2] Allow device-local Pause on the first failed connected transition

**Evidence:** `frontend/src/composables/usePracticeSession.ts:99-114` chooses the local transition branch only when the in-memory offline flag is already true. A downloaded active session initially has that flag false. If the origin disappears before another action/load detects it, Pause flushes an empty outbox, attempts PATCH and reports the transport error without retaining or applying a local pause. The error path has no verified-pack fallback, unlike event submission.

**Reproduction:** download and wait for Verified for offline practice; sever the disposable TCP proxy without sending an online event or reloading; make Pause the first action. The panel remains active with Pause and rating controls, and shows a transport TypeError (`Failed to fetch` in Chromium; `Load failed` in WebKit). No device-local pause is journaled. Confirmed independently in both engines.

**Impact:** the fundamental downloaded-session pause action fails during ordinary connection loss until another operation establishes offline mode. After releasing capture, the session can still accept practice actions even though the learner requested a pause.

**Correction:** for a compatible verified pack, retain/apply the device-local lifecycle intent when a connected transition encounters a transport failure or eligible server-unavailable response. Preserve real version/conflict errors instead of disguising them as offline success, and keep IndexedDB failure visible. Add a browser regression where Pause, and separately Resume from an acknowledged pause, is the first action after origin transport loss.
