## Finding: [P2] A response-body transport failure leaves new practice enabled

**Location:** `frontend/src/api.ts:48` (the successful response's body is read outside the connection-failure catch at lines 30–39). Related admission path: `frontend/src/composables/usePracticeSession.ts:127–137` and `frontend/src/composables/useServerRetry.ts:20–24`.

**Trigger:** Start a connected session, then trigger the normal foreground/online session refresh. Let `/api/v1/sessions/current` deliver HTTP 200 headers and an initial JSON byte, then sever its TCP response before the body finishes. This is a temporary transport failure during an ordinary authoritative read, with no offline practice or concurrent-device requirement.

**Observed in the real built client and real fixture server, in both Chromium and WebKit:** The failed read displays an error, but no `connection-required` screen appears. Recalled becomes enabled again on the retained card. Clicking it without Retry commits a new rating and advances the server cursor from 0 to 1. The selected session was not successfully reloaded through the recovery flow before this new learning command.

| Engine | Visible read error | Connection screen count | Rating enabled before retry | Server cursor after rating |
|---|---|---:|---|---|
| Chromium | `TypeError: Failed to fetch` | 0 | true | 0 → 1 |
| WebKit | `SyntaxError: The string did not match the expected pattern.` | 0 | true | 0 → 1 |

**Cause:** `fetch()` can resolve when response headers arrive; consuming its body can fail later. `api()` marks the server unavailable for a rejected initial fetch or a 5xx status, but propagates a rejected `response.json()` without setting that flag. `load()` catches the read failure and releases `restoring`; the foreground refresh caller ignores its false result. The existing session and attempt then satisfy practice admission. A visible read error alone does not block the controls.

**Supported-scope consequence:** New practice is admitted after a known server-read failure without the required retry and authoritative recovery. This violates the minimal online-only error/retry contract. It does not show speculative rating advancement or lost audio, and it does not require a health platform, probes, offline restoration, or an exhaustive failure matrix to fix. Extend the existing failure handling through response-body consumption and verify that this read failure blocks new practice until actual recovery succeeds, while preserving Stop/cancel.

The body-consumption placement existed at the P3 baseline, which had no P4 global connection admission contract. The finding concerns the incomplete new P4 failure boundary; it does not reopen P3 learning policy.
