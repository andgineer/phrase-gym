## P1.1 — content and cue pack

Twelve authored targets: eight English and four Serbian, across four lessons. Two bounded dialogues reference existing target IDs. Fixtures cover fixed expressions, word retrieval with the target form hidden, construction use with the objective supplied, frames with permitted inflection, contraction, a long phrase, middle/end anchors, complementary stored masks and single-reliable-cue reuse. The coverage seed makes an important previously supplied opening the next retrieval objective. Suitable alternate prepared contexts preserve target identity.

Each target includes complete wording, purpose/meaning, chunks, allowed variants/slots, source identity, reference provenance/preparation metadata and reviewed-cue rationales/competing completions. Broad, leaking, unfamiliar and ambiguous candidates are withheld as rejection fixtures. Initial editorial review was performed by the implementing agent. This is not user approval or native-speaker validation; Serbian wording/translations remain review dependencies.

Eight whole-phrase English WAVs were generated before drilling with the installed macOS Samantha voice. All have nonempty, non-silent PCM data and measurable duration; playback/decoding was exercised in Chromium. Initial sandbox speech calls produced empty files; the preparation check caught those, and clips were regenerated with approved local speech access. No empty assets are delivered. This voice is a disposable engineering fixture, not the production Piper/Edge choice. No listening-quality/accent benchmark is claimed. Actual actor/course and Serbian audio were unavailable; checked local import is implemented without wrong-language fallback.

## P1.3 — audio/storage probe and observed environment

Host: macOS **27.0.1**, build **26A434**. Browser automation: Playwright **1.62.1**, headless Chromium **151.0.7922.34**, Node **20.15.1**. Actual MediaRecorder, playback decoding, IndexedDB transactions, service-worker shell and asset caching were used. Input was a **synthetic microphone stream**, not the user's real microphone or spoken response. Codec detection on this Chromium build reported `audio/webm;codecs=opus` and `audio/mp4`. Captured takes retained their recorder-provided MIME and bytes.
