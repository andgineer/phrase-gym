# Coach architecture comparison

Choose how Coach can turn pasted material into useful practice without teaching an error. Compare two small proofs of concept before changing production prompts, import contracts or the learner interface. Start with A as the control. Test B on the same inputs and selected provider to learn what independently checked examples add. The [input decision](../decision-external-preparation-agent.md#input-decisions) and [content decision](../decision-targeted-drilling.md#basic-wording-practice) define acceptable outputs.

## Two candidates

| | A. Recognize the input and build a basic card | B. Generate a richer card and verify it |
|---|---|---|
| Model work | One call checks the learning language, distinguishes valid forms from obvious typos and rejects unusable input. It identifies the target, any original → corrected form, and whether the complete source has acceptable wording and grammar and fits that target in the learning language. | One small model makes the same recognition decision and proposes complete examples, meaning and cues. A separate call independently checks those judgments against the original, including any rejection, then checks each added claim and every completed example against them. |
| Program work | Check that the original and target can be traced to the input and that the cue conceals the target. Mask only a confirmed source span in a confirmed sentence. Use the target alone when its surroundings fail. No authored example, interpretation or translation is needed. | Use source wording only if both calls confirm the whole sentence and its fit. Apply the same concealment checks. Keep verified additions, drop doubtful or wrong additions, then check the resulting card as a whole. If the remaining examples cannot teach the confirmed target accurately, use A’s basic exercise. Never publish an unchecked rewrite. |
| Risk to test | A source span can match the input while the model still accepts nonsense or changes a valid regional spelling. Structural checks cannot establish linguistic validity. | Both calls can agree on the same wrong correction or meaning. Removing a bad example cannot rescue an invalid target. Count errors the verifier missed as well as valid material it discarded. |

Both designs decline a guessed correction. B publishes only when both calls accept the same target and agree on any correction. If the checker disputes a rejection, a correction or the target itself and the two judgments do not establish the same form, record a terminal unresolved result. Publish nothing, show the reason in the Coach inbox and stop after the second call. Count a valid input lost this way as a false rejection. Disagreement confined to the surrounding sentence or generated additions still permits the agreed target alone. A bounded independent check on a defined class of uncertain A decisions is a possible follow-up if the benchmark exposes a specific failure. Count the extra call, test the revised design on fresh cases, and allow unresolved decisions to end without a card. Authentication or unusable model output is a service failure. Neither design runs a rewrite loop.

Compare content outcomes before synthesis. Separately inspect how each would meet the real package contract, including required explanation, cues, hints, usage contexts, matching reference audio and atomic publication. Record any required contract change for basic cards. Never invent content to fill required fields, count a text-only result as a published card, or relax complete external-package validation for the proof of concept.

## Cases and decision

- Start with a small development set. Reuse relevant prior outputs under ignored `.phrase-gym-coach/` to locate real errors, including repairs that made a card worse. The current repeated review/revision flow can supply a historical reference when outputs already exist. Record its unpinned settings and any unchecked final revision. No new run of that flow is required.
- Before comparing, freeze held-out inputs and expected acceptable decisions, target spans, permitted corrections, and meanings the evidence supports. Include ordinary expressions and isolated polysemous words, source sentences that disambiguate a sense, uniquely recoverable typos, ambiguous near-misses, regional variants, wrong-language input and gibberish. Pair a valid target such as **strongly believe** with a faulty source such as **We strongly believe that this are true**. Expect target-only practice with no faulty sentence or edited quotation. Include unsafe generated additions beside accurate but unpolished controls. For B, present known wrong translations, role reversals and grammatical completions to the verifier as a separate challenge. Distinguish these seeded errors from errors the generator actually made.
- Include English (a valid **colour** and a context-supported **definately → definitely**), German with Russian instructions/help (valid German versus a Russian word as target), and Serbian in Latin and Cyrillic with valid script-specific forms. Include a case where a form is valid in two languages, so the selected language and context matter. Define expected judgments with language-competent evidence, without inventing the learner’s unresolved Serbian help preference. Report each learning language separately. English has the standing demo authorization. Include the other languages in a run when the request covers them. Until measured, list their fixtures and leave their results open. A passing English run qualifies only its tested language.
- Freeze prompts, validators, configuration and fixture IDs before opening the held-out set. Use the same recognition/writing model, explicit effort, case order and per-call limits for both candidates. Bound launches and time in advance, including the verifier. Use synthetic inputs in private measurement files, with no publication, Piper or learner data. A fresh reviewer blind to candidate labels checks every actual outcome, including rejections and claimed corrections, against the original. Keep semantic judgments separate from deterministic checks. Tuning consumes a holdout, so confirm changes on fresh cases.
- For each candidate and language, report the number of eligible inputs, correct accepts/rejects, false rejects, false accepts, incorrect or missed corrections, accepted basic and enriched cards, and service failures. Count materially wrong outputs that would reach practice, and distinguish them from optional improvements to hints or example variety. Report useful cards per valid input and verified rich cards per input eligible for enrichment. Show launches, observable turns/tools and token/cache usage, typical/worst time and quota failures per submission and per useful card. Include discarded attempts. Report fresh measurement review separately from runtime verifier work. Leave unavailable usage unknown.
- Require **zero materially wrong outputs that would reach practice on the frozen benchmark**. Report counts and uncertainty. This observation cannot guarantee production accuracy. Among passing designs, compare safe coverage, lost valid inputs, useful added examples and cost. Rejecting every input cannot qualify. Always producing basic cards earns no credit for enrichment. Prefer A when B offers little additional value. Choose B when it safely preserves valid inputs and adds enough useful contexts to justify the extra time and quota. If neither passes, report the concrete failures and the smallest change worth testing.

## Explicit models and normal CLI environment

Use the [routing and CLI policy](../architecture.md#coach-provider-selection) and [standing authorization](implementation-plan.md#standing-authorization-for-the-local-english-demo). Specify an available model ID and supported effort for every call, including reviewers, and record requested and actual settings. Keep switches and unavailable or unverified results distinct. Reuse news-recap’s read-only [CLI research](../../../news-recap/spec/agents.md), [cost evidence](../../../news-recap/spec/pipeline.md#cost) and existing runner behavior. Remove Coach-specific tool restrictions during implementation, preserving global settings/login, bounded runs, private evidence and secret handling. Verify configured model and effort arguments in adapter tests.

Start A and B on the OpenAI subscription through Codex, with the archived `gpt-5.6-luna` at low effort for recognition and writing. For B, try a separate `gpt-5.6-terra` call at low effort as verifier. Confirm availability and supported effort before running. These are candidates for qualification. If OpenAI is unavailable, record the block. Results from a different route cannot qualify OpenAI.

Then test the selected flow on Gemini subscription, Anthropic subscription and Gemini free, using the same frozen cases, error threshold and measurements. Reuse the archived Anthropic writer candidate `claude-haiku-5-5` at low effort and candidate verifier `claude-sonnet-5` at low effort if B is selected. Run Gemini subscription when existing access identifies that tier. Run Gemini free through news-recap’s Antigravity path with its existing model discovery and pacing. Record the actual route, model and supported effort without credentials. Attribute each result to the tier that actually ran. Mark unavailable subscriptions and unmeasured content quality separately. Compare usefulness and throughput separately for each tier, including basic cards and fewer examples on free. Stop on quota or capacity exhaustion within a measured route. Avoid a model-tier sweep.

Test routing separately with fake authenticated adapters and no network calls. Exercise every Autodetect priority, the case where Gemini and Anthropic subscriptions are both available, every subscription pin with free fallback, the free pin, and the existing CLI overrides. Exercise status-based detection, a subscription-only probe success and denial, and cache reuse and invalidation. A free-model answer cannot qualify a subscription. Include a missing subscription login, a subscription exhausted with paid overage enabled, a free Flash model rename with and without a replacement, a verifier timeout, a semantic rejection and exhaustion of all routes. Check that subscription exhaustion advances to the next permitted route without enabling paid usage or changing global settings. Assert the attempted order, bounded work, preserved pin and distinct service and language outcomes. Replaying an interrupted submission must yield at most one published card and must never reuse an unchecked draft.

Retain the selected flow, per-language evidence and measured settings after the comparison. Implementation then needs regression coverage, real publication with matching audio and the repository gate.
