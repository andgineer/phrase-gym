# Remaining implementation work

This is the execution plan for replacing the Python implementation with Rust while bringing Phrase Gym Server into line with the current specs and delivering Coach as a Windows/macOS Rust GUI app. Keep the Vue/TypeScript client. Implement the specified behavior changes in Rust, without first building a second version of them in Python. Remove completed entries; keep lasting decisions in their linked specs and implementation details in code/tests.

## Scope and migration strategy

The current server provides a substantial foundation, but the latest specs require more than a language port with minor adjustments. Preserve its durability and practice infrastructure; replace superseded behavior deliberately. The following work identifies the boundary between preservation and new implementation, rather than treating all current tests as the desired specification.

| Workstream | Starting evidence and required action |
|---|---|
| Content and durability | Port identity/revision handling, chunk reconciliation, validation and atomic publication from `src/phrase_gym/content/` and `preparation/`. Preserve applicable integration coverage. Replace the human-review publication prerequisite with the specified validated Coach delivery workflow. |
| Practice infrastructure | Port ordered events/receipts, original-response evidence, session replacement, repair spacing, recordings and media from `practice/`, `sessions/` and `media/`. Retain applicable concurrency, retry and browser tests. |
| Prompts and eligibility | `contracts/content.py` and `practice/cues.py` use visible/hidden chunks and chunk-history priority. Implement the specified situation/partner prompts, prompt-level rotation, familiarity provenance, preferred expressions and introduction dependencies. Do not mechanically translate gapped phrase cues. |
| Grading and completion | `practice/reviews.py` excludes supported responses wholesale; `support.py` uses a five-minute window; `observations.py` finalizes through ratings. Implement the hint-failure exception, explicit ungraded study/Next, first spaced recall, unconditional dialogue rehearsal exclusion and persistent declared exposure. Preserve the original-response invariant. |
| Preferences | `settings.py` stores native language and UI mode as one replaceable payload. Introduce revisioned personal profiles and a separately authorized API; retain independent device/UI controls. |
| Inbox and Coach boundary | `api/preparation.py` exposes preparation/retry and handoff routes, not the full scoped worker/preferences/inbox protocol. Reuse lease, identity and publication ideas; implement durable input generations, attachment receipt, fencing, scoped APIs and Coach-only execution. |
| Lifecycle and progress | Add preferred-target switching, retirement/restoration, atomic recreation, changed-assessment evidence, confusable prerequisites, lesson/weekly progress and optional real-call records. Existing cue reporting is not recreation. |
| Toolchain | Replace Python runtime, migrations, test harnesses, Invoke, hooks, packaging, docs generation and GitHub workflows after their Rust/Node replacements pass. Retain no project Python code or Python-dependent development gate. |

The authorities are [architecture](../architecture.md), [learning policy](../decision-core-trainer.md), [card behavior](../decision-targeted-drilling.md), [preferences](../decision-personal-preferences.md), [Coach/inbox](../decision-external-preparation-agent.md), [recordings](../decision-recording-and-comparison.md) and [online-only behavior](../decision-online-only.md). An old test that conflicts with those decisions must become an explicit changed-behavior test, not a compatibility requirement.

Use one temporary transition, with no permanent dual backend, Python bridge or dual writes. The Rust release is the first installed version and keeps no [backward compatibility](../architecture.md#releases-and-data-compatibility) with the Python implementation's databases, APIs or browser data, so nothing is migrated or decoded from it. Both implementations run against separate synthetic databases for comparison. The language-neutral preservation fixtures in `fixtures/preservation/` (HTTP scenarios and scheduler sequences) define that comparison where they encode spec rules; scenarios that only guarded compatibility with Python-era data or clients are retired. The successor record maps every legacy test module to a Rust/client successor or a superseded-behavior replacement. Keep the Python application and its gate until Rust passes the complete material-to-practice and browser gates. Do not touch private learner data, deploy, push or modify source projects as part of implementation acceptance.

## 2a. Implement storage, the request boundary, content and reference media

- Replace the Alembic-shaped Rust schema and its `alembic_version` recognition with a Rust-native, explicitly versioned migration chain starting at its own revision 1. Keep all durable state in one Server-owned SQLite database on local disk, with reference media in core-owned hash-addressed files; no second database or shared network SQLite. Recognize the schema revision before writing and refuse unknown or newer databases untouched. Test fresh initialization, repeated startup and interrupted-migration recovery of the Rust chain. Preserve foreign keys, WAL behavior, bounded busy handling and transaction ownership. Remove the recorded Alembic schemas, their Python drift test and the Rust legacy-recognition tests.
- Port the request boundary before the built client uses Rust: cross-site mutation rejection, trusted host checks and streamed body limits that do not trust `Content-Length`. Host/origin checks are not authentication.
- Port validation separately from publication and library reads. Keep compatible edits on the same target, changed meanings on new targets, stable chunk identities and all-or-nothing package publication. Preserve lookup/search, language scoping, pagination, readiness, lesson/dialogue reads and same-origin built-client serving with correct static paths and headers. Do not port the human-review publication prerequisite, preparation/retry/handoff routes, vault/legacy-note parsers or the echo-words receiver; the batch 4 inbox and job APIs replace them. Seed test content through a test-only path that uses the real validation and publication services and is excluded from release binaries.
- Port reference-media ingestion, container validation and reconciliation. Container validation stays confined to reference media; reconciliation never deletes originals and protects referenced assets.
- Record the missing readiness and library-paging scenarios against Python first. Then make the publication, reference-media, media-reconciliation, lookup-exposure, readiness and paging scenarios pass against Rust and declare them for Rust, extending the shared runner instead of re-encoding expectations. Extend the TypeScript compatibility fixture so every ported endpoint is checked against the retained client's generated types, and update the successor record.

## 2b. Port the practice path, recordings and recovery

- Port single-open-session replacement and immutable manifests; ordered event IDs/sequences, bounded client time and monotonic correction; server-derived attempt bindings; one atomic event/evidence/schedule/receipt transaction; identical retry receipts and changed-payload conflicts. Preserve history when stale content, policy, schedule or closed sessions prevent grading. Make the session-events, session-replacement, practice-repairs, practice-repair-deferral and recordings scenarios pass against Rust and declare them for Rust; extend the TypeScript compatibility fixture to these endpoints.
- Port recording ingestion/retrieval with opaque original bytes, nonempty/base64/schema checks, the MIME allowlist, 12 MiB limit, hashes and immutable context/ID checks. Never decode, inspect containers or transcode learner recordings. Preserve playback range responses, every take including incomplete captures, original timestamps/settings, attempt/exposure links and idempotent upload recovery. Coach and external material credentials cannot read learner recordings.
- Keep the existing Vue client, its microphone capture, audio-session handling, take journal with recovery/retries, playback and their real-browser tests; refactor them only where contracts change. Remove only client code that reads, migrates or retires data left by older client versions: old journal key formats, the old offline service worker and its caches, historical rating flags and their browser harness. The Rust Server serves no worker-retirement script.
- Add consistent database-plus-media backup, isolated restore and matching-snapshot rollback tests for Rust schema revisions. Never roll back only schema while keeping incompatible media/data, or copy only the main file of a live WAL database. Protect referenced active-session, inbox, staged and backup assets during reconciliation.

**Exit:** the built Vue client can browse a synthetic library, practice, record, retry and replay against Rust. Unchanged contracts keep their URLs, payloads and statuses; changed contracts change the retained client in the same commit.

## 3. Add profiles, revised content and target lifecycle

- Add immutable personal-profile revisions, expected-current-revision checks, idempotent mutation IDs, complete atomic validation, originating authorized request and restore-as-new-revision. Distinguish profile read/update, material submission, learner actions and worker permissions; authenticate before accepting work. Retain host/origin protections, but never treat them as authentication or trust arbitrary identity headers.
- Create the current learner's initial profile from the preference decision as personal values, not universal defaults. Keep required Serbian choices unresolved until supplied through the authorized external-agent API. Keep device/UI settings separate; navigation never writes a profile and the frontend has no competing profile editor.
- Define revised prepared-package and session contracts: fixed wording/slots and accepted variants; one or two phrase situations with optional partner turn/audio and one hint; two or three same-sense word contexts or translated chunks; sense cues, help/translation and familiarity provenance; declared cross-target exposures; preference/profile, guide and assessment-condition versions. Validate exact text/language/audio role and structural answer leakage. Semantic quality is a separate acceptance task.
- Store preferred alternatives by communicative intention without merging target identity/history. Switching preference invalidates pending bindings and changes scheduled eligibility while keeping alternatives searchable. Validate cross-entry confusable links and acyclic introduction dependencies; return bounded metadata candidates without exposing learner evidence or recordings.
- Add retirement and Removed-items restoration, retaining histories/recordings and invalidating stale bindings on both transitions. Prepare recreation as one transaction that suspends the expected revision and inserts its inbox request (completed with batch 4). Reject a stale expected revision without partially suspending or enqueueing. Compatible repair retains identity; changed meanings create targets; changed assessment conditions require a fresh independent check.
- The revised package format replaces gapped phrase cues outright; no installed gapped revision needs a history or readiness state. Re-prepare the local 44-phrase pack under the new format only in the separately assessed content work.

**Exit:** profile concurrency/authorization, revised-package validation, identity compatibility, lifecycle invalidation, dependency cycles and the schema revisions they add have deterministic coverage; generated TypeScript contracts describe the new boundary.

## 4. Implement durable inbox, fenced jobs and publication APIs

- Accept typed phrases/words, pasted text and uploaded audio/context with explicit language, sender/item/submission identity, source/group/turn references and attachment roles. Reject URL-only requests; retain URLs inside text/provenance as opaque data. Neither Server nor Coach fetches arbitrary source/media URLs.
- Verify and durably store uploaded bytes before acknowledging input ownership. Preserve originals in core-owned hash-addressed storage with database references. Detect missing, invalid, oversized, truncated or hash-mismatched attachments. Never replace invalid supplied audio with TTS. Reconcile staged/orphan files across transfer, atomic file move and database-commit crashes.
- Preserve original input; note changes, reprocessing and recreation create immutable generations. Pin input, expected target revisions, profile revision and guide version. Same identity/payload returns the same receipt; changed payload conflicts. Complete the atomic suspend-and-recreate workflow while Coach is offline.
- Implement scoped claim, lease renewal, retry, cancellation, staged media/package submission, publication and receipt recovery. Check current generation, lease/fencing token and expected target revisions inside the publication transaction. Expired, cancelled, replaced or superseded workers cannot publish. Preparation/synthesis and upload remain outside that transaction; publication commits content and receipt together.
- Recover a committed receipt after connection loss or worker crash without re-running preparation or inventing identities. Apply bounded attempts, leases and upload/output limits; coordinate durable job state and run-budget accounting with Coach. Preserve committed receipt lookup when a retry follows an expired lease, without allowing the expired worker a new write.
- Expose waiting, preparing, failed-with-reason, pending-delivery and published status. Derive ready, study-only and awaiting-audio counts from committed results/readiness. Unknown meaning fails visibly; a source-faithful item without a defensible prompt may be study-only. Multi-item package publication remains atomic; partial delivery requires explicitly separate packages.
- Add the scoped summary endpoint required by [Coach v1](coach-desktop.md#c3-implement-the-minimal-v1-surface): phrase/word target totals, current inbox status counts and disjoint readiness counts with a snapshot timestamp. Aggregate at Server without exposing raw rows, learner evidence or recordings.
- Add provenance queries and authorized suspension/repreparation by bad guide/adapter version. Workers can read pinned instructions/preferences and bounded relevant candidates, not edit active guides/preferences, access arbitrary rows or obtain learner recordings. Keep material-submit credentials separate from profile-update authority.

**Exit:** with Coach absent and no provider credentials, practice, recording storage, inbox receipt, recreation and preference writes succeed. Concurrent claims, late outputs, conflicting retries, offline delivery, transaction rollback and crash-after-commit recovery pass using fake workers.

## 5. Bring planning, evidence and progress into line with current specs

- Preserve oldest-due ordering, 20-target session capacity and at most five new targets in remaining capacity. Exclude retired, suspended and nonpreferred targets. Introduce default-new material ungraded; accept studied familiarity only with explicit provenance. Rotate prompts by fewest presentations, then oldest presentation, then stable ID; pin prompt/revision/modality and learning context.
- Implement explicit study/Next completion without a rating or claimed speech detection. Allow first independent recall after five minutes and two distinct other finalized targets, or in a later session; provisional next-day learning checks must not block it. Preserve early-practice exclusion for already assessed targets. Keep at most two extra repairs, one consumed review group and no waiting timer.
- Freeze original modality/support/time before reveal or capture exposure; self-rating follows comparison and rerecording cannot replace the evidence. On otherwise eligible independent due review of an assessed target, hint use records Again once at finalization. Apply technical, stale, prior-support, lifecycle, early-practice and consumed-group exclusions first. Hint taps alone never grade; Hard remains correct unaided retrieval.
- After wrong/effortful recall, retain the rating receipt while an ungraded supported say-along ends with Next. Confident recall advances directly. First encounters, explicit study, supported practice and technical interruption must not acquire invented memory success/failure. Verify retries across both rating and completion transitions.
- Make every full dialogue run rehearsal regardless of visible script, preserving ratings/takes without FSRS changes. Store declared cross-target exposure and prevent immediate independent checks of rehearsed answers. Do not let the incidental-lookup timeout erase explicit rehearsal support. Independent partner-turn cards remain possible when otherwise eligible.
- Gate new confusable partners on the prerequisite's independent recall on a later learning day in the pinned profile timezone. Test midnight/DST boundaries, cross-entry links, unavailable prerequisite release and visible active-blocking reasons. No dedicated mixed-drill feature.
- Add lesson counts for active preferred targets recalled at their last independent check and overdue targets, distinguishing evidence from changed assessment conditions. Weekly progress counts distinct eligible reviewed targets in the profile learning week. Optional real-call phrase selections and used/no chance/forgot marks have no scheduling effect. Repeated repairs/rehearsal cannot inflate progress. Expose learner-authorized progress reads and retry-safe real-call writes through generated contracts for batch 6.

**Exit:** tests cover each eligibility/exclusion ordering, first-check exception, lifecycle race, original-response binding, prompt rotation, dialogue exposure and timezone boundary. Scheduler preservation fixtures still pass; changed product behavior has new expectations instead of copied legacy assertions.

## 6. Integrate the retained Vue client and Rust Coach

- Add the optional real-call flow in Vue: select two or three phrases for a concrete opportunity, then record used/no chance/forgot for each. Optional means the learner can omit the activity; its client workflow is part of this batch. Test persistence after reload and ambiguous-write retries against the real Server, and verify all marks leave schedules and eligible-review progress unchanged.
- Add the + drop panel with clipboard read only on its initiating tap, empty fallback, optional note, explicit Send and recent statuses. - Replace `tests/browser_server.py`, `browser_preparation.py` and their fixture dependencies with a Rust test server/seed harness plus Node/Playwright setup as appropriate. - Exercise the complete desktop drop → durable inbox receipt → offline wait → claim → prepare/synthesize → transfer → atomic publish → practice/replay path with fake agent/speech processes. Include malformed output, timeout, cancellation, lost submission/publication receipts, stale fencing and missing audio. Start Server alone with no Coach configuration/provider credentials and confirm published practice remains available.

**Exit:** Rust domain/integration suites and retained/updated client tests pass; Chromium and WebKit use the Rust server and built client, including lesson/weekly progress and real-call workflows. Coach desktop/process/drop/statistics acceptance passes on Windows and macOS as specified in its plan. Native WebKit recording coverage remains on macOS as in current CI. Fake process boundaries establish software conformance; real semantic/listening/device acceptance remains separate below.
