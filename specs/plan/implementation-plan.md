Implement the specified behavior changes in Rust, without first building a second version of them in Python. Remove completed entries; keep lasting decisions in their linked specs and implementation details in code/tests.

## Scope and migration strategy

The current server provides a substantial foundation, but the latest specs require more than a language port with minor adjustments. Preserve its durability and practice infrastructure; replace superseded behavior deliberately. The following work identifies the boundary between preservation and new implementation, rather than treating all current tests as the desired specification.

| Workstream | Starting evidence and required action |
|---|---|
| Content and durability | Extend the bounded English production intake/publication path to the remaining revised package forms. Port applicable chunk identity reconciliation from `preparation/` with those forms (batch 3). |
| Practice infrastructure | Rust sessions, ordered events/receipts, original-response evidence, repairs, recordings and device settings serve every endpoint the retained client calls, with concurrency, retry and preservation coverage. The retained client and its applicable Chromium/WebKit suites use Rust; the preparation lifecycle suite retains a temporary Python harness until batches 4 and 6. |
| Prompts and eligibility | The Rust `prompts` and `planning` modules use visible/hidden chunks, chunk-history priority and the current due/new planner. Implement the specified situation/partner prompts, prompt-level rotation, familiarity provenance, preferred expressions and introduction dependencies. Do not mechanically translate gapped phrase cues. |
| Grading and completion | Rust `practice/reviews.rs` excludes supported responses wholesale; `practice/support.rs` uses a five-minute window; `practice/observations.rs` finalizes through ratings; dialogue script exposure is ordinary five-minute support. Implement the hint-failure exception, explicit ungraded study/Next, first spaced recall, unconditional dialogue rehearsal exclusion and persistent declared exposure. Preserve the original-response invariant. |
| Preferences | Make session and client reads use the revisioned personal profile, leaving only independent device/UI controls in `settings.rs`. |
| Inbox and Coach boundary | Extend the bounded English inbox protocol to the remaining package forms, recreation and scoped statistics; connect Coach Send and the selected isolated CLI runner. Replace the remaining Python preparation/handoff harness. |
| Lifecycle and progress | Add preferred-target switching, retirement/restoration, atomic recreation, changed-assessment evidence, confusable prerequisites, lesson/weekly progress and optional real-call records. Existing cue reporting is not recreation. |
| Toolchain | Replace Python runtime, migrations, test harnesses, Invoke, hooks, packaging, docs generation and GitHub workflows after their Rust/Node replacements pass. Retain no project Python code or Python-dependent development gate. |

The authorities are [architecture](../architecture.md), [learning policy](../decision-core-trainer.md), [card behavior](../decision-targeted-drilling.md), [preferences](../decision-personal-preferences.md), [Coach/inbox](../decision-external-preparation-agent.md), [recordings](../decision-recording-and-comparison.md) and [online-only behavior](../decision-online-only.md). An old test that conflicts with those decisions must become an explicit changed-behavior test, not a compatibility requirement.

Use one temporary transition, with no permanent dual backend, Python bridge or dual writes. The Rust release is the first installed version and keeps no [backward compatibility](../architecture.md#releases-and-data-compatibility) with the Python implementation's databases, APIs or browser data, so nothing is migrated or decoded from it. Both implementations run against separate synthetic databases for comparison. The language-neutral preservation fixtures in `fixtures/preservation/` (HTTP scenarios and scheduler sequences) define that comparison where they encode spec rules; scenarios that only guarded compatibility with Python-era data or clients are retired. The successor record maps every legacy test module to a Rust/client successor or a superseded-behavior replacement. Keep the Python application and its gate until Rust passes the complete material-to-practice and browser gates. Do not touch private learner data, deploy, push or modify source projects as part of implementation acceptance.

## 5. Bring planning, evidence and progress into line with current specs

- Preserve oldest-due ordering, 20-target session capacity and at most five new targets in remaining capacity. Exclude retired, suspended and nonpreferred targets. Introduce default-new material ungraded; accept studied familiarity only with explicit provenance. Rotate prompts by fewest presentations, then oldest presentation, then stable ID; pin prompt/revision/modality and learning context.
- Implement explicit study/Next completion without a rating or claimed speech detection. Allow first independent recall after five minutes and two distinct other finalized targets, or in a later session; provisional next-day learning checks must not block it. Preserve early-practice exclusion for already assessed targets. Keep at most two extra repairs, one consumed review group and no waiting timer.
- Freeze original modality/support/time before reveal or capture exposure; self-rating follows comparison and rerecording cannot replace the evidence. On otherwise eligible independent due review of an assessed target, hint use records Again once at finalization. Apply technical, stale, prior-support, lifecycle, early-practice and consumed-group exclusions first. Hint taps alone never grade; Hard remains correct unaided retrieval.
- After wrong/effortful recall, retain the rating receipt while an ungraded supported say-along ends with Next. Confident recall advances directly. First encounters, explicit study, supported practice and technical interruption must not acquire invented memory success/failure. Verify retries across both rating and completion transitions.
- Make every full dialogue run rehearsal regardless of visible script, preserving ratings/takes without FSRS changes. Store declared cross-target exposure and prevent immediate independent checks of rehearsed answers. Do not let the incidental-lookup timeout erase explicit rehearsal support. Independent partner-turn cards remain possible when otherwise eligible.
- Gate new confusable partners on the prerequisite's independent recall on a later learning day in the pinned profile timezone. Test midnight/DST boundaries, cross-entry links, unavailable prerequisite release and visible active-blocking reasons. No dedicated mixed-drill feature.
- Add lesson counts for active preferred targets recalled at their last independent check and overdue targets, distinguishing evidence from changed assessment conditions. Weekly progress counts distinct eligible reviewed targets in the profile learning week. Optional real-call phrase selections and used/no chance/forgot marks have no scheduling effect. Repeated repairs/rehearsal cannot inflate progress. Expose learner-authorized progress reads and retry-safe real-call writes through generated contracts for batch 6.

**Exit:** tests cover each eligibility/exclusion ordering, first-check exception, lifecycle race, original-response binding, prompt rotation, dialogue exposure and timezone boundary. Scheduler preservation fixtures still pass; changed product behavior has new expectations instead of copied legacy assertions.
