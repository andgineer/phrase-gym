# Online-only trainer — authoritative product decision

Accepted 2026-10-13 by explicit user instruction: **remove all offline work functionality**. Phrase Gym requires a live server for practice, lookup, library and settings. This overrides the downloaded-session/offline decision, prior P4 plans, the offline state model and any queue-only training proposal. Historical review/evidence records remain history; they do not authorize restoring offline training.

## Connected behavior

No downloads, prepared-session packs, selected-media caches, cached app shell, offline library/session restoration, predicted attempts/support/grades, local cursor/completion or local pause/resume exist. UI progress, dialogue steps, repairs, support and results come from server receipts. Ordinary online repair policy remains intact. P4 covers connected recording/session reliability, accessibility and actual-device evidence; P5/P6 remain separate.

Connection failure hides usable learning/settings screens and blocks new exercise, recording, help, rating and lifecycle commands. A connection/retry screen may show retained-write/audio recovery status. Already active media stays stoppable/cancellable; cleanup may retain interrupted bytes under the initiating context. `navigator.onLine` is only a signal to verify, never evidence that practice may resume. Retry uses actual server requests, retries original pending writes and reloads authoritative state before enabling practice. Keep this a minimal error/retry path using established journals; no per-action health probes, global availability framework, exhaustive outage matrix or seamless offline recovery promise. Lost receipts cannot advance the client speculatively.

## Retained evidence is not offline training

IndexedDB may retain already initiated server writes, acknowledged history and each pending take for retry. Preserve original IDs, payloads, event order, immutable first response/support, content/capture binding, hashes/completeness and conditional acknowledgement deletion. Application-lifetime volatile audio, exclusive capture leases and old-card cleanup remain. Never reset backend progress/recordings or the entire origin store. No new learning commands are generated while connection/reconciliation is blocked; terminal media cleanup observations may be retained safely.

Old queued payloads are historical evidence. A narrowly bounded compatibility decoder may accept the retired repair-deferral flag only for sessions issued by the earlier planner, preserving canonical payload/idempotent receipts and their old queue. New online sessions and generated API contracts do not expose that flag. No client creates new deferred/offline ratings or interprets old packs as a playable trainer. Obsolete packs and display preferences/lifecycle fallbacks are retired without consuming pending event/take/start/transition/exposure records or acknowledged history.

## Retiring earlier clients

The old worker URL serves only a minimal network-only retirement worker so already registered versions can update. It removes only Phrase Gym's owned shell/selected-media caches, refuses offline network fallbacks, unregisters itself and does not auto-reload over live/volatile audio. The current client retires matching owned registrations/caches and obsolete pack data before normal use. No routine worker registration, offline installation, update UI or cached navigation remains. Preserve pending evidence during this cleanup; do not clear unrelated origin storage. Ordinary pages/API responses prevent stale HTTP app caching.
