# Online-only practice

Practice, lookup, library, core Settings and inbox API operations require the live learning core. Server reads and receipts own card position, support, repairs, lifecycle and results. No downloads, offline installation, cached trainer or predicted local progression.

The laptop preparation worker may be offline. Published lessons, reference playback, recording storage, scheduling, inbox submission and personal-preference API updates continue using the core and its single database. Waiting preparation is visible as waiting for the worker and never causes a global learning failure. An accepted recreation request suspends that defective target while other practice continues. No live worker/provider call belongs on a practice request path.

Loss of the core connection hides normal learning/Settings and blocks new server actions. Already active media remains stoppable/cancellable, preserving interrupted bytes under their initiating context. Retry resends original pending writes and reloads authoritative state before enabling learning. Browser connectivity signals are hints, not proof of recovery. Keep this a small error/retry flow, without per-action health probes or a general availability framework.

IndexedDB retains initiated writes, acknowledged checkpoints and pending takes for retry. Preserve original IDs, payloads, order, support and capture bindings. Conflicts remain retained without resequencing; a new action uses the reconciled server card. These journals protect evidence, not offline practice or guaranteed survival of browser eviction. External API senders likewise retain unacknowledged submissions when the core is unavailable.

Client upgrades remove only owned obsolete caches/registrations and pack/display data. The retirement worker at the old URL is network-only and unregisters itself. Neither cleanup path clears pending evidence, unrelated origin storage or reloads active/volatile audio. Narrow decoding of old queued payloads preserves their receipt identity; new contracts expose no offline practice behavior.
